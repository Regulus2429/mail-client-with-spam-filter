# Windows 使用手册

本系统用于受控课程实验。以下命令在项目根目录的 PowerShell 中运行；用两个终端分别运行服务端和客户端。默认使用 TLS，明文仅用于本地抓包对比。以下账号仅为实验例子，密码在提示时输入且不显示。

## 1. 准备环境

安装 Python 3.11 或更新版本、Git 和 OpenSSL，确认 `py --version`、`git --version`、`openssl version` 可运行。实际验证环境为 Python 3.11；团队成员建议统一 Python 版本。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m mailproject --help
```

所有命令直接指定虚拟环境 Python，无需修改 PowerShell 脚本执行策略。若本机未安装 3.11，可调整创建虚拟环境时的版本号。

## 2. 创建测试账号

```powershell
.\.venv\Scripts\python.exe -m mailproject add-user alice@example.test
.\.venv\Scripts\python.exe -m mailproject add-user bob@example.test
```

每个账号分别输入两次非空密码。账号为 ASCII 邮箱地址；账号和带盐密码哈希保存在 `data/mail.sqlite3`。这些是系统内的测试账号，不是真实邮箱账号。

## 3. 生成测试证书并启动加密服务

本例的自签名证书只用于实验。证书含 `localhost` 与 `127.0.0.1` 两个身份，客户端连接时必须使用其中之一；局域网使用时，应将服务器 IP 或 DNS 名写入 SAN 并使用同一地址连接。`tests/openssl.cnf` 是项目自带的最小 OpenSSL 配置，避免依赖系统默认配置位置。

```powershell
New-Item -ItemType Directory -Force certs | Out-Null
openssl req -config tests/openssl.cnf -x509 -newkey rsa:2048 -nodes -days 365 -keyout certs/server-key.pem -out certs/server-cert.pem -subj /CN=localhost -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1'
.\.venv\Scripts\python.exe -m mailproject server --cert certs/server-cert.pem --key certs/server-key.pem
```

服务默认只监听本机，SMTP 使用 STARTTLS 端口 1587，POP3 使用直接 TLS 端口 1995。按 Ctrl+C 停止。对于局域网演示，用 `--host 0.0.0.0` 监听并根据需要配置 Windows 防火墙，仅在可信实验网络中使用。客户端将 `--host` 设置为服务器 IP，`--ca` 指向通过可信渠道获得的服务器证书；绝不要把私钥复制到客户端。证书 SAN 必须包含该 IP，例如生成时将 `IP:192.168.1.10` 加入 `-addext` 的列表。

## 4. 发送、接收和查看

另开 PowerShell，切换到项目目录。发送纯文本邮件（提示输入 Alice 的密码）：

```powershell
.\.venv\Scripts\python.exe -m mailproject send --user alice@example.test --to bob@example.test --subject '测试邮件' --text '你好，计算机网络！' --ca certs/server-cert.pem
```

带 HTML 和附件的例子：将 HTML 正文保存为 UTF-8 的 `demo.html`，并替换附件路径为实际存在的文件：

```powershell
.\.venv\Scripts\python.exe -m mailproject send --user alice@example.test --to bob@example.test --subject '附件测试' --text '这是纯文本备用正文。' --html-file demo.html --attach 'D:\示例\图片.png' 'D:\示例\文档.pdf' --ca certs/server-cert.pem
```

接收端提示输入 Bob 的密码：

```powershell
.\.venv\Scripts\python.exe -m mailproject list --user bob@example.test --ca certs/server-cert.pem
.\.venv\Scripts\python.exe -m mailproject fetch --user bob@example.test --ca certs/server-cert.pem
```

`list` 显示邮件编号、稳定 UID 和字节数。`fetch` 将新邮件保存至 `downloads` 下以账号编码命名的子目录，输出具体 `.eml` 路径；重复下载时按 UID 跳过已保存文件。查看邮件并提取附件：

```powershell
.\.venv\Scripts\python.exe -m mailproject view 'downloads\复制上一步输出的目录\复制输出的文件名.eml' --attachments-dir downloads\attachments
```

输出目录已有同名附件时会拒绝覆盖；可改用新目录。HTML 正文作为文本显示，不在客户端中执行。

## 5. 明文对照

停止 TLS 服务后，在服务端终端运行：

```powershell
.\.venv\Scripts\python.exe -m mailproject server --plain --smtp-port 1025 --pop-port 1110
```

客户端在 `send` 后添加 `--plain --port 1025`；`list` 或 `fetch` 后添加 `--plain --port 1110`，无需 `--ca`。用 Wireshark 抓取相应端口，可观察明文 SMTP/POP3 命令及内容；使用 TLS 端口时，应用层内容被加密。`AUTH PLAIN` 的 Base64 编码不是加密，因此只应在受控环境用明文模式。

## 6. 模拟中间人攻击

保持第 3 节的 TLS 服务运行。生成一张与真实服务器不同的自签名证书并启动受控代理：

```powershell
openssl req -config tests/openssl.cnf -x509 -newkey rsa:2048 -nodes -days 7 -keyout certs/fake-key.pem -out certs/fake-cert.pem -subj /CN=localhost -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1'
.\.venv\Scripts\python.exe tools/mitm_demo.py --fake-cert certs/fake-cert.pem --fake-key certs/fake-key.pem --upstream-ca certs/server-cert.pem
```

代理监听本机 1996，试图冒充 POP3 服务器。另一个终端将客户端指向代理，但只信任真实服务器证书：

```powershell
.\.venv\Scripts\python.exe -m mailproject list --user bob@example.test --port 1996 --ca certs/server-cert.pem
```

应出现证书验证错误，代理报告连接被拒绝；密码不会被发送给该代理。将端口改回 1995 后应能成功连接。可截取两次运行结果和 Wireshark 抓包作为演示材料。

## 7. 常见问题

- `CERTIFICATE_VERIFY_FAILED`：确认客户端使用的证书是服务器证书，连接地址在证书 SAN 中，且系统时间正确。
- `Mailbox locked`：同一账号已有 POP3 会话，退出该会话后再试；不同账号可以同时访问。
- 连接失败：确认服务已启动、端口一致；局域网下检查监听地址、证书 SAN、防火墙和两台机器的连通性。
- 附件路径或 HTML 文件找不到：使用存在的绝对路径。所有文件和账号数据只存于本地实验目录。
